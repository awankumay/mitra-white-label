# Branding (White Label) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Core Branding (TODO §10, PRD §28) — organization-level white-label branding (company name, logo, dark logo, favicon, primary/secondary color, footer text) built on top of the existing Settings System (M7), applied at runtime to the Filament panel (including the login page) and to the header of transactional emails.

**Architecture:** `core/Branding/BrandingResolver` reads `branding.*` keys through the existing `Core\Contracts\SettingsRepository`, with an explicit fallback to the sole `Organization` row in the database when there is no authenticated user (login page, email) — because `Core\Contracts\OrganizationContext` is user-membership-based and cannot resolve an organization before login. `core/Branding/BrandingServiceProvider` registers the `branding.*` key definitions directly into the existing `Core\Settings\SettingsRegistry` (reusing the M7 registry/repository/cache machinery — no new table, no new cast type). `app/Filament/Pages/Settings/BrandingSettings.php` is the only write surface, always targeting `SettingScope::Organization` for the current user's organization. `app/Providers/Filament/AdminPanelProvider.php` and a hand-written override of Laravel's `resources/views/vendor/mail/html/header.blade.php` read through `BrandingResolver` to apply branding at runtime.

**Tech Stack:** Laravel 13, Filament 5 (Schemas), Spatie Permission + Filament Shield, Livewire 4, Pest/PHPUnit (class-style, project convention), UUIDv7.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-19-branding-design.md` — read it before starting; every decision below traces back to it.
- **Architecture (ADR-005):** `Core\` must NOT use `App\`/`Modules\`; Core non-UI must NOT use Filament. Only `app/Filament/Pages/Settings/BrandingSettings.php` (Task 2) and `app/Providers/Filament/AdminPanelProvider.php` (Task 3) touch Filament. `core/Branding/*` stays framework-agnostic (only `Core\*` and `Illuminate\Support\Facades\Storage`).
- **No new schema.** Branding values are stored in the existing `settings` table (M2/ADR-011) via the existing `Core\Contracts\SettingsRepository`. Do NOT create a migration.
- **No new cast type.** Every `branding.*` key uses `'type' => 'string'` in the registry — including `branding.logo`/`branding.dark_logo`/`branding.favicon`, which store a disk **path**, not file bytes. `DatabaseSettingsRepository::cast()` (M7) is not modified.
- **`branding.*` definitions are hardcoded inline in `Core\Branding\BrandingServiceProvider::boot()`** — NOT read from `core/Config/core.php` like `core.settings.definitions` is. This is a deliberate deviation from the M7 pattern (spec §6) so `Core\Branding\*` stays one self-contained package, following `Core\Context\ContextServiceProvider`. Only `core.branding.disk` lives in `core/Config/core.php`.
- **Scope:** every `branding.*` key allows exactly `[SettingScope::Organization, SettingScope::System]`. No `SettingScope::Unit`/`SettingScope::User` — Organizational Unit branding is out of scope (spec §8).
- **Write surface:** `BrandingSettings` page only ever calls `SettingsRepository::set()`/`getForScope()` with `SettingScope::Organization` and the current user's `OrganizationContext::organizationId()`. There is no System-tier UI in v1.
- **Anonymous-context read fallback (spec §3.2, verified empirically this session):** `BrandingResolver::get()` resolves the organization id as `OrganizationContext::organizationId() ?? Core\Organization\Models\Organization::query()->value('id')`. This is ONLY inside `BrandingResolver` — it must NOT be added to `DatabaseSettingsRepository`'s generic cascading (that stays user-context-only, unchanged, used by other settings like `app.timezone`).
- **`ashrafic/filament-white-label` stays active** (`composer.json` unchanged, `->whiteLabel()` call in `AdminPanelProvider` unchanged). Our branding wiring calls are added strictly **after** `->whiteLabel()` in the panel chain, so they win (`brandName()`/`brandLogo()`/`darkModeBrandLogo()`/`favicon()` are scalar-overwrite; `colors()` is additive-by-key — both cases confirmed by reading `vendor/filament/filament/src/Panel/Concerns/{HasBrandLogo,HasBrandName,HasColors}.php`).
- **Email markdown customization requires `config/mail.php['markdown']['paths']`.** This project's `config/mail.php` does NOT ship the `'markdown'` key (verified: stock Laravel 13's mail config stub omits it). Without adding `'markdown' => ['theme' => 'default', 'paths' => [resource_path('views/vendor/mail')]]`, ANY file placed under `resources/views/vendor/mail/html/` is silently ignored by `Illuminate\Mail\Markdown::render()`. This was confirmed by direct experimentation in this session — do not skip this config change.
- **Only `resources/views/vendor/mail/html/header.blade.php` needs to exist** — NOT the full `vendor:publish --tag=laravel-mail` tree. `Illuminate\Mail\Markdown` registers the `mail::` namespace with TWO hint paths (`resources/views/vendor/mail/html`, then the framework's own `vendor/laravel/framework/.../Mail/resources/views/html`) and falls through to the second for any view not present in the first — confirmed by direct experimentation. Do NOT run `vendor:publish` for this task; hand-write only the one file.
- **`Filament\Panel::getBrandName()` already falls back to `config('app.name')` on its own** (`vendor/filament/filament/src/Panel/Concerns/HasBrandName.php`); our `brandName()` closure's own `?? config('app.name')` is intentionally-redundant belt-and-braces, not required for correctness — keep it anyway, it is explicit spec behavior (spec §3.4).
- **Permission format `action:subject`** (PRD §19): `view:branding` / `update:branding`. Add both to `config/filament-shield.php['custom_permissions']`. Create them in tests via `Permission::firstOrCreate(['name' => ...])` — this project has no permission seeder.
- **Livewire statePath pitfall (same as M7):** registry keys use dots (`branding.company_name`) but form field names must use underscores (`branding_company_name`); convert with `str_replace('.', '_', $key)`.
- **Test conventions:** PHPUnit class-style (`class XxxTest extends TestCase`), `use RefreshDatabase;`. `BrandingSettings` page tests live in `Tests\Feature\Settings` (co-located with `ApplicationSettingsPageTest`, same page-namespace `App\Filament\Pages\Settings\*`); everything else branding-specific lives in `Tests\Unit\Branding` / `Tests\Feature\Branding`.
- **Attaching a user to an organization in tests:** use the existing `App\Models\User::organizations(): BelongsToMany` relation — `$user->organizations()->attach($org->id)` — NOT `app(OrganizationContext::class)->set($org)` (that only mutates the in-memory singleton for the current process, bypassing the real `Core\Context\ContextResolver::firstOrganization()` DB-driven lookup that `actingAs($user)` + HTTP/Livewire requests actually exercise).
- **Out of scope — do NOT implement in this plan** (spec §8): uninstalling `ashrafic/filament-white-label`; System-tier branding UI; Organizational Unit-level branding; email button/theme CSS color customization; multi-organization support beyond the single-org fallback; live preview; image cropping.

```php
<?php

namespace Core\Branding;

use Core\Contracts\OrganizationContext;
use Core\Contracts\SettingsRepository;
use Core\Organization\Models\Organization;
use Core\Settings\Enums\SettingScope;
use Core\Settings\SettingsRegistry;
use Illuminate\Support\Facades\Storage;

final class BrandingResolver
{
    public function __construct(
        private readonly SettingsRepository $settings,
        private readonly SettingsRegistry $registry,
        private readonly OrganizationContext $context,
    ) {}

    public function get(string $key): mixed
    {
        $orgId = $this->context->organizationId() ?? Organization::query()->value('id');

        if ($orgId !== null) {
            $value = $this->settings->getForScope($key, SettingScope::Organization, $orgId);

            if ($value !== null) {
                return $value;
            }
        }

        return $this->settings->getForScope($key, SettingScope::System)
            ?? $this->registry->definition($key)['default'];
    }

    public function url(string $key): ?string
    {
        $path = $this->get($key);

        return $path ? Storage::disk(config('core.branding.disk'))->url($path) : null;
    }
}
```

```php
<?php

namespace App\Filament\Pages\Settings;

use Core\Contracts\OrganizationContext;
use Core\Contracts\SettingsRepository;
use Core\Settings\Enums\SettingScope;
use Core\Settings\SettingsRegistry;
use Filament\Forms\Components\ColorPicker;
use Filament\Forms\Components\FileUpload;
use Filament\Forms\Components\TextInput;
use Filament\Notifications\Notification;
use Filament\Pages\Page;
use Filament\Schemas\Schema;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Storage;

/**
 * @property-read Schema $form
 */
class BrandingSettings extends Page
{
    protected string $view = 'filament.pages.settings.branding-settings';

    protected static ?int $navigationSort = 51;

    protected static ?string $title = 'Branding Settings';

    /** @var array<string, mixed>|null */
    public ?array $data = [];

    public static function getNavigationGroup(): ?string
    {
        return trans('nav.administration');
    }

    public static function canAccess(): bool
    {
        return (bool) Auth::user()?->can('view:branding');
    }

    public function mount(): void
    {
        if (! app(OrganizationContext::class)->has()) {
            Notification::make()
                ->warning()
                ->title('Belum ada organisasi aktif')
                ->send();
        }

        $repository = app(SettingsRepository::class);
        $registry = app(SettingsRegistry::class);
        $orgId = app(OrganizationContext::class)->organizationId();

        foreach ($registry->keysInGroup('branding') as $key) {
            $field = str_replace('.', '_', $key);
            $this->data[$field] = ($orgId !== null
                ? $repository->getForScope($key, SettingScope::Organization, $orgId)
                : null) ?? $registry->definition($key)['default'];
        }

        $this->form->fill($this->data);
    }

    public function form(Schema $schema): Schema
    {
        return $schema
            ->components([
                TextInput::make('branding_company_name')
                    ->label('Nama Perusahaan'),
                FileUpload::make('branding_logo')
                    ->label('Logo')
                    ->image()
                    ->disk(config('core.branding.disk'))
                    ->directory('brand'),
                FileUpload::make('branding_dark_logo')
                    ->label('Logo (Dark Mode)')
                    ->image()
                    ->disk(config('core.branding.disk'))
                    ->directory('brand'),
                FileUpload::make('branding_favicon')
                    ->label('Favicon')
                    ->image()
                    ->disk(config('core.branding.disk'))
                    ->directory('brand'),
                ColorPicker::make('branding_primary_color')
                    ->label('Warna Primer'),
                ColorPicker::make('branding_secondary_color')
                    ->label('Warna Sekunder'),
                TextInput::make('branding_footer_text')
                    ->label('Teks Footer'),
            ])
            ->statePath('data')
            ->disabled(fn (): bool => ! app(OrganizationContext::class)->has());
    }

    public function save(): void
    {
        $orgId = app(OrganizationContext::class)->organizationId();
        abort_unless(Auth::user()?->can('update:branding') && $orgId !== null, 403);

        $repository = app(SettingsRepository::class);
        $registry = app(SettingsRegistry::class);
        $disk = Storage::disk(config('core.branding.disk'));
        $state = $this->form->getState();

        foreach ($registry->keysInGroup('branding') as $key) {
            $field = str_replace('.', '_', $key);
            $newValue = $state[$field];

            if (in_array($key, ['branding.logo', 'branding.dark_logo', 'branding.favicon'], true)) {
                $old = $repository->getForScope($key, SettingScope::Organization, $orgId);
                if ($old !== null && $old !== $newValue && $disk->exists($old)) {
                    $disk->delete($old);
                }
            }

            $repository->set($key, $newValue, SettingScope::Organization, $orgId);
        }

        Notification::make()
            ->success()
            ->title('Branding disimpan')
            ->send();
    }
}
```
